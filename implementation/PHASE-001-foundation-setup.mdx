# PHASE-001 Foundation Setup

## Goal

Establish the technical foundation for Life Mirror MVP without implementing Daily Mirror product features.

## Implemented Foundation

- Existing Next.js frontend and Institute site remain intact.
- Fastify provides an independently deployable API runtime.
- PostgreSQL provides identity and session persistence.
- Authentication uses server-side sessions and stores only hashed session tokens.
- Identity storage is explicitly separated from future Personal Mirror data.
- LLM access is isolated behind a provider interface with disabled and OpenAI-compatible implementations.
- GitHub Pages continues to deploy the static Institute frontend.
- The API has a separate Docker image and development Compose environment.
- CI verifies type safety, unit tests and both build targets.

## Intentional Boundaries

PHASE-001 does not implement:

- Daily Mirror screens
- Liuyao execution
- Knowledge retrieval
- Reflection generation endpoints
- Personal Memory tables or APIs

Those capabilities begin only after PHASE-002 is approved.

## Runtime Topology

```text
Frontend
↓
API Runtime
↓
PostgreSQL

API Runtime
↓
LLM Provider Interface
```

## Environment Progression

Development → Staging → Production

All secrets and provider credentials are supplied through environment variables.

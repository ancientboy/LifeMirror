# LifeMirror：Phase 011–019 完整执行路线图

> 状态：执行中（以 D1／Worker 为唯一线上数据权威）  
> 更新：2026-08-11  
> 唯一实施原则：不引入多 Agent。维持 `Harness + deterministic tools + Memory Runtime + Context Builder + Shiguang` 的受控运行时。

## 0. 北极星与边界

### 北极星

拾光会自然记得用户的生活，在合适的时候给出有判断、有温度、并且随互动越来越贴近用户的回应。

六爻、塔罗、命盘、占星是拾光理解与表达的工具，不是彼此割裂的产品主角。

### 不变原则

1. **主动理解，而非被动记事。** 后端可以从互动中形成暂定观察；用户的明确反馈用于强化、修正或推翻，不是唯一的记忆开关。
2. **观察不是诊断。** 一次情绪、一次工具结果、一次关系冲突不能变成永久人格标签。
3. **现实优先，象征辅助。** 用户明确说过和后来发生过的现实事实优先于命理／占卜解释。
4. **可追溯、可修正、可淡化、可删除。** 每项系统观察必须能回到证据，并支持失效与撤回。
5. **唯一线上权威。** 登录用户的 D1／Worker 产品数据是唯一权威；本地缓存仅限游客或可丢弃的读取缓存。
6. **隐私与关系隔离。** A 的关系信息不能被用于 B；用户数据不用于模型训练。
7. **先验证日用与分享，再扩大社交。** 不用未验证的好友关系链稀释核心体验。

## 1. 总体执行顺序

```text
011A 数据权威与同步
  → 011B 主动理解引擎
  → 011C Context Builder 与遗忘
  → 012 每日拾光闭环
  → 013 拾光人格与聊天体验
  → 014 专业玩法统一
  → 015 关系演练验证
  → 016 分享与轻社交
  → 017 评测、隐私与可观测性
  → 018 经过验证的社交扩展
  → 019 规模化与技术壁垒
```

每个 Phase 必须完成：数据契约、D1 迁移／兼容、单元测试、Worker/D1 关键路径测试、生产构建、GitHub 提交；线上部署只从已提交的 `main` 对应版本进行。PostgreSQL 不属于 Sites 生产发布前提。

## 当前实现边界（2026-08-11）

- 已实现基础：账户权威写入与删除 tombstone、D1 记忆事件／观察／修订、受限 Context Builder、Daily／回顾、工具结果续聊、分享与私密关系安全、匿名产品指标、运行审计、告警、持久任务、个人上下文图谱。
- 已实现但仍需线上验收：跨设备同步、任务失败重放、模型主备、关系举报／屏蔽与导出／删除路径。它们必须在已部署的 D1 版本上通过端到端验收，才可标为完整关闭。
- 本轮补齐：`expression_preferences` 是用户明确选择的回复风格（语气、篇幅、追问方式），可修改、导出和独立删除；它不会被当作人格事实，也不会进入匿名指标。
- 仍未完成：版本化金标准评测自动门禁、社交通知频控与运营处置、可配置成本预算、离线版本化重跑、备份恢复与灾难演练。后续工作不得以文档或提交标题替代这些验收。

## P0：可靠、主动理解、每日可回来

### Phase 011A：数据权威与同步收口

**目标**：先保证“记忆不会乱”，再让系统变得更聪明。

**交付**

- 定义单一线上写入／读取路径：Worker API + D1。
- 统一游客、本地缓存、登录迁移、账户恢复、删除与导出契约。
- 清理旧的重复写入路径与快照反向覆盖风险。
- 对历史、明确事实、人物、Open Loop、Daily 回访分别定义 ownership、版本与删除语义。
- 为删除建立 tombstone／revision，防止旧设备缓存同步时将删除内容复活。
- 把部署元数据写入构建产物或健康检查，能追溯 Sites 运行的 GitHub commit。

**验收**

- 同一账号两设备新增、修改、删除后结果一致。
- 删除的内容刷新、重新登录和旧缓存上传后均不复活。
- 游客升级为账号后只迁移一次且不丢历史。
- 页面只读取权威数据源；写入失败可见且可重试。
- `typecheck`、单元测试、生产构建和关键 Worker/D1 路径全绿。

### Phase 011B：主动理解引擎

**目标**：拾光能随互动自然形成“当前理解”，不是等待用户逐条授权保存。

**数据模型**

- `memory_events`：原始对话片段、工具结果、行动、现实回访；保存来源、时间、关系作用域与用户授权。
- `memory_observations`：主题、偏好、情绪／沟通模式、关系动态等自动观察。
- `memory_evidence_links`：观察与原始事件的证据关系。
- `memory_revisions`：纠正、合并、删除、失效、矛盾。
- `belief_state`：`emerging | active | fading | contradicted | deleted`。
- `confidence`：由重复频率、独立场景、时间新鲜度、语言确定性、后续一致性计算。

**行为**

- 从聊天、工具、行动、关系互动异步抽取候选事件与观察。
- 单次低证据内容最多生成 `emerging` 观察，不得成为长期标签。
- 跨时间、跨场景重复出现的主题可升为 `active`。
- 相反信息、用户否认或时间久未出现时，自动降权、淡化或标为矛盾。
- 高敏感类别（健康诊断、性取向、政治、宗教、犯罪、未确认第三方私密信息）禁止自动形成长期观察。
- 只在高影响推断上提供轻量“这不太像我”入口；普通对话不打断用户。

**验收**

- 连续多次提及同一现实主题时，拾光能自然且准确提起。
- 一次性抱怨不会被错误概括为人格。
- 用户纠正后，后续上下文不再使用旧观察。
- 每一条被召回的观察都可查到证据与时间。

### Phase 011C：Context Builder 与遗忘机制

**目标**：让拾光“想起该想起的”，不把所有历史塞入 prompt。

**交付**

- 一个统一 `Context Builder`，为聊天、Daily、周镜像、关系演练输出不同的受限上下文。
- 混合排序：当前任务相关性、语义相关性、时间衰减、用户明确保存、现实回访、主题重复度、关系作用域、置信度。
- Token 预算、去重、冲突处理和不可召回状态。
- 明确事实、原始事件、自动观察、稳定主题分层输出。
- 删除／矛盾／过期内容在任何 Context 中均不可召回。

**验收**

- 近期现实优先于陈旧推断。
- A 与 B 的关系资料严格隔离。
- 已删除、已纠正、已矛盾的内容不出现在聊天、Daily、周镜像或演练。
- 每个调用类型有固定上下文预算与可测试排序结果。

### Phase 012：每日拾光闭环

**目标**：给用户每天自然回来的理由。

**交付**

- 今日一句：基于活跃主题、未完成事项、近期现实进展与时间节律生成。
- 轻量当日行动：可做、未做、先放下，不制造打卡压力。
- 晚间回访：围绕当天主题，自然承接，不写成表单问卷。
- 周镜像：只汇总真实行动、回访与已验证／活跃主题，展示“这周正在发生什么”。
- Daily、回访和周镜像均写入既有事件流，并成为后续理解的证据。

**验收**

- 每天内容会随用户近况变化，不是换日期的泛化运势。
- 积累至少两次真实记录后，周镜像能说明具体变化及依据。
- 未使用工具的用户也能获得连贯体验。
- 不显示“系统正在分析你”“置信度”等破坏体验的内部措辞。

### Phase 013：拾光人格与聊天体验

**目标**：后端完成判断，拾光自然呈现；不再像导师或工具引导页。

**交付**

- 统一系统人格、回复结构与跨功能语气。
- 优先给出判断、陪伴和下一步，不用“你觉得呢”把分析作业抛给用户。
- 聊天页与探索／工具入口完全分离；只保留一个输入框。
- 工具结果页可自然续聊，且续聊带入有限、正确的结构化事实。
- 降级路径返回诚实、简洁、仍有用的回应，不能露出内部参数或 Markdown 残渣。

**验收**

- 同一用户在聊天、Daily、工具结果的拾光声音一致。
- 不出现过度提示工具、双输入框、英文参数、重复标题或空降级文案。
- 高风险现实问题有适当边界但不打断正常陪伴。

## P1：把工具、关系与分享接回同一条主线

### Phase 014：专业玩法统一协议

**目标**：四项玩法成为连续理解的输入，而不是四个一次性页面。

**交付**

- 统一 `规则事实 → 专业解释 → 拾光表达 → 事件写入` 协议。
- 六爻：卦、变卦、世应、用神、动爻和凶吉等本地规则事实。
- 塔罗：完整 78 张、正逆位、牌阵位置与牌间关系。
- 命盘：四柱、五行、十神、喜忌、大运／流年与人生领域映射。
- 占星：星体、宫位、相位、命主星、行运／推运。
- 工具结果只作为象征性上下文；不得自动覆盖现实事实或写入人格判断。

**验收**

- 每类结果先有可验证专业事实，再有差异化的拾光表达。
- 结果可在历史中复用，用户主动重新测算时才创建新事件。
- 分享卡、聊天与周镜像不会把象征解读误说成现实事实。

### Phase 015：关系演练验证

**目标**：验证用户是否需要“为一段真实关系做沟通准备”。

**交付**

- 人物只记录用户提供的事实、关系边界、互动事件和用户观察。
- 演练前显示“这是沟通准备，不是人格预测”。
- 情境演练、消息草稿与可选“像／不太像”校正。
- 关系 context 仅读取当前人物及可授权共享的全局事实。

**验收**

- 不把对第三方的推测写成事实。
- A/B 关系绝不串线。
- 用户可在真实沟通后留下结果，供后续演练校准。
- 以重复使用和演练后回访衡量需求，不以好友数衡量。

### Phase 016：分享与轻社交

**目标**：先验证分享欲，再投资重社交。

**交付**

- 分享卡三种声线：朋友、清醒、神秘。
- 一句话能独立成立，默认脱敏，不暴露生日、关系对象、完整档案与私人聊天。
- 分享链接承接回应／继续与拾光聊天。
- 记录分享创建、打开、回应、回流等最小漏斗。

**验收**

- 三种声线内容确有差异，不是同一段文字换标题。
- 分享内容无敏感字段泄露。
- 可以测量从生成到打开、回流的链路。

## P2：用数据证明“更懂你”，再验证社交

### Phase 017：评测、隐私与可观测性

**目标**：不凭主观感觉发布记忆功能。

**交付**

- 匿名金标准集：召回、时间、关系隔离、删除、纠错、象征／现实边界、Daily 个性化。
- 回归测试：用户否认、旧观察过期、A/B 人物混淆、游客迁移、跨设备删除。
- 最小产品指标：首日有效对话率、次日／7日回访、工具后继续聊天率、Daily 完成率、分享率、关系演练复用率。
- 记忆与 LLM 调用审计：来源、读写、失败、延迟、成本、隐私范围。
- 数据导出、删除、保存授权和保留周期的用户控制。

**验收**

- 每次发布自动执行关键评测与隐私回归。
- 仪表板能定位召回失败、错误记忆、同步失败与成本异常。
- 指标事件不包含可直接识别的聊天正文。

### Phase 018：经验证的社交扩展

**启动条件**：分享或关系演练已显示明确复用需求与可接受安全边界。

**交付**

- 在现有 LifeMirror ID／私密关系基础上，逐步增加双向邀请、接受、撤回、屏蔽、举报与权限控制。
- 关系镜像必须双方明确授权，允许单方撤销。
- 通知中心、频率控制、反骚扰与运营处置流程。

**验收**

- 邀请、拒绝、撤销、屏蔽、举报端到端可用。
- 无授权时绝不暴露关系内容。
- 社交功能不降低核心聊天／Daily 完成率。

## P3：形成可积累的技术壁垒并规模化

### Phase 019：个人理解图谱、规模化与壁垒

**目标**：让“使用越久，拾光越难被替代”成为可证明的产品事实。

**交付**

- 可追溯的个人生活上下文图谱：现实事实 ↔ 当下困扰 ↔ 象征工具 ↔ 后来反馈 ↔ 表达偏好。
- 每位用户的表达策略学习：直接／温柔／清醒、篇幅、工具偏好、何时适合追问。
- 异步提取、队列、失败重放、任务幂等、模型供应商降级、缓存与成本预算。
- 版本化 prompt／抽取器／Context Builder；支持离线重跑而不覆盖用户原始事实。
- 数据生命周期、备份恢复、灾难演练、权限审计与公开发布风控后台。

**验收**

- 用户长期使用后，召回准确率与个性化评分显著优于冷启动。
- 可说明某条理解的证据、状态与修订历史。
- 单用户成本、延迟、失败率处于明确预算内。
- 可导出、可删除、可迁移，且删除后不可被重建任务恢复。

## 2. 关键数据与运行时原则

```text
互动 / 工具 / Daily / 回访
        ↓
不可变原始事件
        ↓
异步抽取候选观察
        ↓
证据聚合与置信度更新
        ↓
当前理解（可淡化、矛盾、删除）
        ↓
任务化 Context Builder
        ↓
拾光自然表达
        ↓
新互动持续校准
```

- 原始事件保留“发生了什么”；自动观察保留“拾光目前怎么理解”；稳定主题保留“长期反复出现什么”。
- 自动观察可以主动产生，但必须有证据、时间、关系范围和状态。
- 模型永远不能直接把自己的推断写成用户明确事实。
- 非同步推断任务必须幂等、可重放、可审计。

## 3. 发布与质量门禁

每个 Phase 发布前必须满足：

1. 明确数据迁移与回滚方案。
2. 对新增写入、读取、删除、纠错与权限路径有测试。
3. 执行 TypeScript 类型检查、单元测试、生产构建与关键 Worker/D1 路径测试。
4. 审查敏感数据是否进入日志、埋点、分享内容或不应有的 prompt。
5. GitHub `main` 是唯一发布源码；Sites 发布记录对应 commit SHA。
6. 线上观测无新增错误峰值，再开始下一个 Phase。

## 4. 里程碑判断

- **P0 完成**：拾光不会乱记、会自然形成暂定理解，并给用户每日回来的连续理由。
- **P1 完成**：四种象征工具、聊天、关系演练和分享都进入同一条个人理解主线。
- **P2 完成**：团队能量化证明记忆正确性、留存和分享／关系需求，而不是凭感觉迭代。
- **P3 完成**：形成经用户授权、可追溯、可校准的个人生活上下文图谱；模型可替换，但长期高质量个人理解与反馈闭环不可复制。

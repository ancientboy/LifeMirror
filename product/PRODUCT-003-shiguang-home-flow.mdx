# 拾光优先的完整产品流程

LifeMirror 不是四个小游戏的集合。拾光是主产品，六爻、命盘、塔罗、占星是她在不同问题中调用的观察工具。

## 主流程

1. 欢迎页：建立“双生世界”品牌感，只解释产品，不直接进入工具。
2. 身份入口：用户选择登录或游客模式；游客记录保存在当前设备，登录后迁移并通过 D1 账户同步。
3. 拾光首页：默认进入常规对话，并以“今日拾光、上次事件续问、状态快捷回应”降低再次打开的表达成本。
4. 工具建议：用户主动选择，或拾光在有明确理由时建议一个最合适的工具。
5. 工具体验：完成六爻、命盘、塔罗或占星的确定性计算与结构化解释。
6. 结果回流：结果页保留 Q 版拾光与追问；返回首页时可继续围绕同一主题对话。
7. 保存与镜像：用户主动保存后进入个人镜像；登录账户跨设备同步，第一次保存立即形成初始 Mirror DNA。
8. 关系回流：用户可以通过 LifeMirror ID 或分享链接连接好友；回应、申请与双方关系镜像重新回到拾光对话。

## 工具选择原则

- 六爻：一件具体、当下、存在变化条件的问题。
- 命盘：长期结构、时间节奏、五行与大运流年。
- 塔罗：情绪、关系、选择与尚未说清的内在冲突。
- 占星：本命人格结构、行星宫位相位及长期自我理解。

## 体验边界

- 不把工具入口放在身份确认之前。
- 不把工具做成四个互不关联的 H5 小游戏。
- 不用模板逐字动画伪装成 LLM；模型不可用时明确显示设备内引导模式。
- 不强迫用户做测试；常规聊天本身必须是完整可用的第一路径。
- 任何结果都回到现实验证、用户选择和后续对话，不以一次报告结束关系。

## Return behavior

- 命盘和占星的本命资料只填写一次，两者共用唯一出生资料。
- 本命结果不是每日重复抽取内容；只有资料修正时重算本命结构。
- 再次打开时优先展示“上次那件事后来怎样了”，而不是要求用户重新描述背景。
- 常规聊天在用户授权后读取相关的明确事实和已保存镜像，不读取无关全部历史。
- 未来站外主动触达必须是用户明确选择，并提供频率、冷却、免打扰和随时关闭。

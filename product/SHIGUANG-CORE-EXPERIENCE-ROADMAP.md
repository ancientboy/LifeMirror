# 拾光核心体验改造路线图

## 0. 文档定位

本路线图解决的不是“LifeMirror 还有哪些功能没做”，而是一个更关键的问题：

> 技术底座与功能已经较完整，但产品定位没有被用户直接感受到，拾光还不足以让用户喜欢、信任并持续回来。

它承接已经交付的 P0–P3 工程能力，不重做 D1、Memory Runtime、Context Builder、四项确定性工具、账户、关系、评测与可靠性基础。后续改造只围绕用户可感知的核心体验展开：

1. 第一次使用，用户觉得拾光听懂了自己；
2. 再次回来，用户发现拾光记得前因后果；
3. 事件有结果后，拾光会追问“后来怎么样”并修正理解；
4. 长期使用后，用户感到拾光越来越贴近自己，而不是每次重新开始。

本轮暂停按功能数量推进新的 P 系列。任何新增功能都必须证明它增强了上述主循环。

---

## 1. 产品定位收敛

### 1.1 面向用户的一句话

> **拾光，一个会记得后来发生了什么的 AI 朋友。**

辅助说明：

> 你说过的人、发生过的事和一直绕不开的问题，拾光会放在一起理解，不会每次从头认识你。

### 1.2 核心用户

- 不太愿意向现实中的人表达，但愿意先和 AI 说的人；
- 容易在关系里反复猜测，希望有人帮自己看清当下的人；
- 不需要被教育或持续反问，而需要被理解、获得判断和具体下一步的人；
- 愿意通过六爻、塔罗、命盘、占星等方式表达感受，但最终关心的仍是现实关系与生活结果的人。

### 1.3 核心任务

拾光负责：

- 听懂用户正在经历的事情；
- 识别没有直接说出的情绪和真正担心；
- 区分现实事实、暂时推断与象征性参考；
- 给出明确但不过度武断的判断；
- 给出当前可执行的一步；
- 记住待观察事项，并在合适的时候追问结果；
- 根据现实反馈加强、修正或推翻之前的理解。

### 1.4 不再呈现的产品形象

- 命理工具合集；
- 心理咨询师或人生导师；
- 总把问题反问给用户的思考教练；
- 喜欢解释系统机制、记忆策略和风险术语的 AI；
- 一有困惑就推荐塔罗或六爻的导流助手。

### 1.5 定位验收

邀请首次用户体验 3 分钟后询问“你觉得这是什么产品？”：

- 合格：用户认为拾光是会记事、会继续跟进、能帮助处理真实事情的 AI 朋友；
- 不合格：用户主要认为它是算命、塔罗、心理测试或普通聊天工具。

## 2. 唯一核心循环

```text
用户说一件正在发生的事
        ↓
拾光理解情绪、事实与真正担心
        ↓
给出判断与一个具体下一步
        ↓
保存为等待现实回应的事件
        ↓
下次自然追问“后来怎么样”
        ↓
记录行动、对方回应与实际结果
        ↓
修正对用户、人物和关系的理解
        ↓
下一次给出更贴近用户的回应
```

四项玩法、Daily、周镜像、分享和关系功能都必须接入这条主线，不得形成彼此割裂的独立体验。

---

## 3. 强制执行顺序

执行顺序固定为：

```text
S0 定位与体验原则冻结
 → S1 拾光回复引擎
 → S2 “后来怎么样”现实反馈闭环
 → S3 首页与聊天入口收敛
 → S4 四项玩法回归辅助能力
 → S5 每日与每周连续体验
 → S6 分享与轻关系传播
 → S7 真实用户验证
 → S8 会员与收费实验
```

S1、S2、S3 是本轮最高优先级。前三项未通过验收，不进入后续阶段。

---

## 4. S0：冻结定位与体验原则

### 目标

让产品、设计、Prompt、Context、页面和埋点围绕同一个用户价值工作。

### 交付

- 所有核心页面统一使用本路线图的一句话定位；
- 首页、聊天、Daily、工具结果统一以“拾光”作为主角；
- 内部保留 Life Mirror Theory、Mirror DNA、Memory Runtime 等概念，但默认不向普通用户解释；
- 建立禁止文案清单、拾光表达原则和关键场景范例；
- 新需求模板增加“是否增强核心循环”的判断项。

### 门禁

- 产品首屏不再需要依靠说明文档解释定位；
- 团队能用同一句话解释拾光；
- 新需求如果无法关联核心循环，默认不开发。

## 5. S1：重做拾光回复引擎

### 目标

让用户第一次对话就感觉“它听懂了，而且没有把问题重新丢给我”。

### 5.1 内部判断顺序

每轮回复前，受控运行时应形成：

1. 用户此刻最明显的情绪；
2. 用户真正担心或期待的事情；
3. 当前能够确认的现实事实；
4. 与当前问题最相关的人物、事件和历史结果；
5. 拾光的暂时判断及不确定边界；
6. 当前最适合的一步；
7. 是否应创建、延续或关闭一个待回访事件。

这些结构只用于后端，不向用户显示分析标签、置信度或检索过程。

### 5.2 默认回复结构

大部分普通对话控制为三段：

1. 接住此刻感受，但不机械复述；
2. 给出明确判断，并说明最关键的现实依据；
3. 给出一个具体下一步，必要时说明等待什么信号。

示例：

> 你难受的不只是他没回，而是你又开始怀疑自己是不是太主动了。现在还不能说明他在疏远你，但你今晚别再补发消息，先把判断留到他真正回应之后。

### 5.3 拾光允许拥有的表达

- “这确实挺伤人的。”
- “我不太相信他这个解释。”
- “你这次可能真的想多了。”
- “这句话先别发，我觉得你明天会后悔。”
- “等一下，这和你上次说的情况不太一样。”
- “我记得你上次也是先替对方找理由。”

表达可以直接、有温度、有轻微个性，但不能假装确定第三方心理，也不能把推断写成事实。

### 5.4 默认禁止

- “你可以想一想……”
- “你内心真正需要的是什么？”
- “这或许是一个觉察自己的机会。”
- “答案最终还是在你心里。”
- 没有现实理由的连续反问；
- 大段复述用户原话；
- 多个互相抵消的可能性；
- 非必要免责声明；
- 主动暴露工具、Prompt、Context、置信度或模型状态；
- 高频建议用户使用塔罗、六爻等工具。

### 5.5 Context Builder 输入

每轮只提供当前任务所需内容：

- 最近对话；
- 当前事件与状态；
- 当前相关人物；
- 用户明确事实；
- 最相关的少量历史事件；
- 拾光上次判断和建议；
- 用户后来反馈的现实结果；
- 用户明确选择的表达偏好。

不得把完整人生档案全部塞入 Prompt。已删除、已纠正、关系范围不符或仅为低证据推断的内容不得召回。

### 5.6 评测与门禁

建立不少于 100 个匿名或合成真实场景的版本化评测集，覆盖：

- 暧昧与等待回复；
- 争吵、冷战与分手；
- 朋友、家人和同事关系；
- 自我怀疑、反复纠结和冲动表达；
- 用户纠正拾光；
- 记忆命中、记忆缺失和错误记忆；
- 无需工具、适合工具和不应推荐工具的场景；
- 高风险边界场景。

核心评分：

- 是否给出可辨识的判断；
- 是否像熟悉的朋友而非咨询师；
- 是否避免过度反问和空泛套话；
- 是否正确、自然地使用历史；
- 是否给出可执行的一步；
- 是否让用户愿意继续说；
- 是否避免虚构事实或第三方内心。

发布门禁：核心场景综合通过率不低于 80%，且错误记忆、关系串线和高风险越界为零容忍项。

## 6. S2：“后来怎么样”现实反馈闭环

### 目标

把 LifeMirror 的长期记忆从后台能力变成用户能够直接感受到的核心体验，并形成真正可积累的数据壁垒。

### 6.1 事件生命周期

```text
正在发生
 → 已给出判断／建议
 → 等待用户行动或现实回应
 → 已获得结果
 → 修正理解
 → 已结束 / 继续观察
```

### 6.2 必须分开保存

- 用户明确说过的事实；
- 拾光当时的暂时判断；
- 拾光给出的建议；
- 用户是否采取行动；
- 对方或现实真实如何回应；
- 最终结果；
- 原判断被加强、修正或推翻的状态。

模型推断不得自动升级为用户事实。象征工具结果不得覆盖现实结果。

### 6.3 用户体验

- 重新打开产品时，优先承接未结束事件；
- 问法自然、具体，例如“昨天你说他突然不回消息，后来有回应吗？”；
- 用户可以回答“有了”“还没有”“不想再提”或直接说经过；
- “不想再提”应关闭主动追问，但不等于系统擅自删除历史；
- 用户反馈后，下一轮判断必须体现现实结果；
- 拾光发现原判断错误时应自然承认并修正。

### 6.4 门禁

- 用户无需重述背景即可继续一件未结束的事；
- 回访不会问错人物、时间或事件；
- 同一事件不会被重复创建成多个 Open Loop；
- 关闭、删除或拒绝追问后不再主动打扰；
- 现实反馈能真实影响后续对话、Daily 与周镜像。

## 7. S3：首页与聊天入口收敛

### 目标

新用户一打开就知道可以直接说一件事；老用户一打开就感到拾光记得上次发生了什么。

### 7.1 首页信息顺序

1. 拾光自然问候；
2. 最值得承接的一件未结束事件；
3. 与近期状态相关的“今日一句”；
4. 唯一聊天输入框；
5. 轻量探索入口；
6. 固定底部导航：首页／探索／镜像／我的。

### 7.2 必须调整

- 聊天页只保留一个输入框；
- 工具入口与聊天输入区分离；
- 首屏不要求用户先选择分析方式；
- 不展示 Memory、Mirror DNA、Context Builder 等内部术语；
- 玩法页和结果页不丢失底部导航；
- 首页不同时堆放关系、报告、玩法、分享和多个行动卡；
- 新用户获得清晰的第一句引导，老用户优先获得连续上下文。

### 7.3 门禁

- 首次用户无需教程即可开始说一件正在发生的事；
- 老用户首屏优先显示真实未结束事件，而非通用欢迎语；
- 从首页到首次发送消息的主要路径不超过一次选择；
- 在主流移动端首屏不存在双输入框、主行动竞争或布局遮挡。

---

## 8. S4：四项玩法回归拾光的辅助能力

### 目标

六爻、塔罗、命盘和占星不再是四个平行产品，而是拾光理解与表达的不同视角。

### 分工

- 命盘、星盘：稳定出生底图与时间节律；
- 塔罗、六爻：用户主动选择的当下象征视角；
- 拾光：结合现实上下文给出判断；
- 现实反馈：最终校准依据。

### 结果页顺序

1. 一句最重要的结论；
2. 拾光针对原问题的直接解读；
3. 当前下一步；
4. 可展开的专业依据；
5. 继续和拾光聊；
6. 保存或分享。

### 门禁

- 工具结果携带原问题、人物和事件上下文回到拾光；
- 用户不需要重复填写或重新讲述；
- 使用工具后自然进入继续对话或等待现实反馈，而非“测完结束”；
- 工具不会被频繁、无理由地主动推荐；
- 专业事实、拾光表达和现实事实边界清晰。

---

## 9. S5：每日与每周连续体验

### 目标

让 Daily 成为生活连续性的体现，而不是每日随机换皮文案。

### 每日内容优先级

1. 未结束事件；
2. 最近反复出现且仍活跃的主题；
3. 命盘／星盘时间节律；
4. 用户最近主动使用的塔罗／六爻；
5. 数据不足时的轻量通用内容。

### 每日只保留三项

- 今天一句判断；
- 今天值得留意的一件事；
- 一个可以直接采取的小行动。

不解释内容来源，不展示“系统分析”、置信度或数据拼装过程。

### 每周镜像只回答

- 这周用户最在意什么；
- 哪件事情出现了变化；
- 拾光之前有什么判断被验证或需要修正；
- 下周最值得留意什么。

### 门禁

- 连续三天的内容能体现同一事件或主题的进展；
- 现实已经改变后，Daily 不继续使用过期判断；
- 没有命盘、星盘或工具记录的用户也能获得连贯内容；
- Daily 能自然导向继续对话或事件反馈，但不制造打卡压力。

---

## 10. S6：分享与轻关系传播

### 目标

分享用户觉得“这句话很像我”的瞬间，而不是输出一份冗长玩法报告。

### 分享内容

- 拾光说中用户的一句话；
- 一段关系状态的隐晦表达；
- 用户想让某个人看见但不方便直接说的话；
- 朋友能够轻量回应的关系卡。

### 分享卡默认结构

- 一句核心文案；
- 拾光角色；
- 极少量来源标记；
- LifeMirror 标识；
- 可选回应入口。

### 门禁

- 朋友、清醒、神秘三种声线内容真正不同；
- 不包含生日、完整档案、聊天正文、第三方身份等敏感信息；
- 用户不编辑也能直接分享；
- 分享打开、回应和回流可被匿名测量；
- 个人核心体验未达标前，不扩大复杂好友社交功能。

---

## 11. S7：真实用户验证

### 目标

停止仅用功能完成度和内部主观感受判断产品，验证用户是否真的喜欢拾光。

### 测试规模

先邀请 30–50 名目标用户，至少完成 7 天观察；其中一部分完成 30 天持续观察。

### 核心指标

| 指标 | 定义 | 首轮目标 |
| --- | --- | --- |
| 首次继续对话率 | 首次收到拾光回复后继续发送至少一条有效消息 | ≥ 60% |
| 有效事件创建率 | 首日形成至少一个有具体人物／事情的事件 | ≥ 40% |
| 次日回访率 | 新用户次日再次打开并产生有效行为 | ≥ 30% |
| 7 日留存 | 第 7 日仍产生有效对话、Daily 或事件反馈 | ≥ 15% |
| 现实反馈率 | 等待结果的事件获得一次“后来怎么样”反馈 | ≥ 25% |
| 记忆正确率 | 用户确认拾光引用历史准确且自然 | ≥ 90% |
| 工具后续聊率 | 工具结果后继续和拾光产生有效对话 | ≥ 35% |
| 主动分享率 | 用户主动生成或分享内容 | ≥ 5% |

首轮目标是产品判断线，不是对外承诺。样本量不足时不得把波动解释成确定结论。

### 定性问题

- 哪一句让用户觉得拾光听懂了？
- 哪一次记忆让用户感到惊喜或被冒犯？
- 用户是否觉得拾光有鲜明但舒服的人格？
- 用户为什么第二天回来，或者为什么没有回来？
- 用户愿意把什么内容发给朋友？
- 如果停止使用，用户最舍不得什么？
- 用户能否用一句话向朋友解释拾光？

### 通过条件

只有当用户持续表现出“愿意继续说、愿意回来反馈、认为拾光记得准确”时，才进入收费设计。若数据不达标，优先回到 S1–S3，不用新功能掩盖核心体验问题。

---

## 12. S8：会员与收费实验

### 启动前提

- S1–S3 全部通过体验门禁；
- 至少完成一轮真实用户验证；
- 次日、7 日留存和现实反馈出现可重复信号；
- 用户能明确说出愿意为哪种持续价值付费。

### 初步权益原则

免费层保留基础聊天、基础玩法和基本记忆；付费层围绕长期价值，而不是只出售更多消息：

- 更完整的长期主题轨迹；
- 每周／月度镜像；
- 人物与关系事件连续理解；
- 沟通演练、结果回访与理解修正；
- 更长的上下文连续性和个性化表达。

建议先进行小规模创始用户实验，不在验证前预设高价或复杂会员等级。

---

## 13. 本轮暂缓事项

在 S1–S3 通过前，以下事项默认暂缓：

- 新增第五种命理／占卜玩法；
- 扩大公开社交广场或陌生人匹配；
- 为了展示技术增加多 Agent；
- 继续增加首页卡片和入口；
- 与核心循环无关的大规模视觉翻新；
- 复杂等级、积分、连续签到和游戏化体系；
- 仅按消息额度设计会员；
- 把更多内部分析术语展示给用户。

必要的稳定性、安全性、隐私和生产故障修复不受暂缓限制。

## 14. 发布纪律

每一阶段必须：

1. 明确用户问题、行为改变和验收指标；
2. 先更新对应评测，再修改运行时或页面；
3. 保持 `Harness + deterministic tools + Memory Runtime + Context Builder + Shiguang` 架构，不引入无约束多 Agent；
4. 运行类型检查、单元测试、Worker 契约测试和生产构建；
5. 检查现实／推断／象征边界、关系隔离与敏感数据；
6. 只从 GitHub `main` 对应提交部署 Sites；
7. 完成线上 smoke test 和指标观察后，才能开始下一阶段。

---

## 15. 最终完成定义

本轮优化不是以“页面和任务全部开发完成”为结束，而是以用户体验信号为准：

- 第一次：用户感觉拾光听懂了；
- 第二次：用户发现拾光记得；
- 事情有结果：拾光会问后来怎么样；
- 拾光判断错误：它能根据现实结果修正；
- 连续使用：用户感觉拾光越来越像一个认识自己的朋友；
- 向朋友介绍：用户能自然地说出“它会记得我说过的人和后来发生的事”。

只有这些体验被真实用户反复验证，LifeMirror 的长期记忆、关系数据、四项工具和个人理解图谱才真正转化为用户愿意留下并付费的产品壁垒。

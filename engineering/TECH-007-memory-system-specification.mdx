# TECH-007 Memory System Specification

## Purpose
Define how Life Mirror forms long-term understanding.

## Memory Types
- Short-term Memory
- Event Memory
- Reflection Memory
- Pattern Memory
- Mirror DNA Memory

## Principle
Store meaningful understanding, not all conversations.

## PHASE-003 Boundary

Implemented:

- Event Memory
- Reflection Memory
- Pattern Memory foundation
- retrieval and user lifecycle controls

Implemented after PHASE-003:

- Personal Mirror Dashboard and timeline
- first-event initial Mirror DNA observation
- relevant explicit-fact and saved-mirror retrieval in normal Shiguang chat
- daily home follow-up based on the latest saved mirror
- account synchronization of consent settings, explicit facts and saved mirror history

Deferred:

- server-native Mirror Graph
- asynchronous proactive delivery outside the product
- semantic embeddings and background LLM extraction with human review

## Extraction Contract

The source is an explicitly saved `reflection_event`. The deterministic processor produces:

```text
Event Memory
  title / topic / trigger / summary / occurred_at

Reflection Memory
  observation / insight / reflection_question / action_suggestion / concepts
```

The processor is idempotent per source event and version. User-corrected fields survive reprocessing.

Event Memory classification uses only the user-authored question and deterministic event facts. AI-generated observation or insight is stored separately as Reflection Memory and cannot introduce an event fact or Pattern topic. Both the legacy flat KNOWLEDGE-003 snapshot and the enhanced nested schema remain processable.

## Pattern Contract

An initial Mirror DNA observation may be displayed after one saved event, but it must be labelled as provisional and remain tied to that event. A Pattern Memory is created only when the same topic or symbolic concept has at least two independent source events. It contains:

- neutral, non-diagnostic title and summary
- signal count
- confidence capped below certainty
- first and last observation time
- source-event evidence links

Patterns are observations, not personality labels. Deleting a pattern creates an owner-scoped suppression so it is not silently recreated. Pattern extraction never updates Mirror DNA in PHASE-003.

## Retrieval Contract

Retrieval uses only visible Event and Reflection Memory owned by the authenticated user. It can filter by title, topic, summary, insight or concepts. Responses explicitly identify personal reflection usage and `trainingData: false`.

The Daily Mirror Runtime may retrieve up to five visible recent Event memories and five evidence-backed Patterns as optional reflection context. Hidden records are excluded. The Runtime must treat context as evidence rather than certainty and may not convert an inference into a user fact.

## Dashboard Preparation

`GET /api/v1/memories/summary` provides counts, current reflection, recent patterns and timeline entries for the full API runtime. The Sites runtime synchronizes the same user-controlled inputs through account data and derives the provisional first-event display locally; it does not promote a single event to a Pattern.

## Normal chat memory

When the user enables memory, the chat runtime retrieves up to five relevant explicit facts and up to three relevant saved mirror events. Retrieval is topic-scoped. Temporary chat disables both reading and writing for the current conversation. Explicit “请记住…” instructions can create a saved fact; ordinary sentences are not silently promoted to permanent fact memory.

This architecture follows a common agent pattern: one orchestrator chooses tools and relevant memory, deterministic tools produce domain facts, and the language model writes the response. It does not use several autonomous agents to independently rewrite the user's identity.

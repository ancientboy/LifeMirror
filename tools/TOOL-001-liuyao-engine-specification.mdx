# TOOL-001 Liuyao Engine Specification

## Architecture Position

```text
User Question
  ↓
Liuyao Tool
(Casting + Calculation + Traditional Analysis)
  ↓
KNOWLEDGE-003
(Classical Texts + Explanations)
  ↓
Mirror Runtime
(Context Assembly + Reflection)
  ↓
Shiguang Persona
(Humanized Communication)
  ↓
User
```

The existing Liuyao Tool is the only divination implementation in Life Mirror. A `v2` tool, parallel Python package, duplicate API or alternate calculation path is prohibited.

The Tool output is consumed by KNOWLEDGE-003 and KNOWLEDGE-004, but neither layer is part of this Tool. Fields named `humanMeaning`, `userFacingReflection`, Shiguang response text or advice must never be added to `LiuyaoResult`.

## Responsibility Boundary

### Tool

The Tool performs deterministic casting, calculation, traditional rule execution and structured analysis. It computes line values, hexagrams, palace, Shi/Ying, Najia, Six Relations, Five Elements, Six Spirits, void branches, useful-god selection, strength, generation/control relationships, hidden/flying spirit and heuristic timing.

The Tool does not write emotional explanations, user advice, reflection text or Shiguang dialogue.

### Knowledge

KNOWLEDGE-003 stores classical hexagram/line text, traditional explanations and rule meanings. It explains computed fields but never calculates an individual reading.

### Runtime and LLM

Mirror Runtime assembles the user question, visible personal context, Tool facts, KNOWLEDGE-003 classical material and KNOWLEDGE-004 reflection mappings. The LLM translates supplied material into Shiguang reflection. It must not calculate Liuyao, infer missing calculation inputs, invent classical meanings, or replace/contradict Tool analysis.

The runtime envelope is assembled by `server/reflection/context.ts`. The output is a six-field Shiguang response plus an explanation trace linking classical basis, Tool evidence, reflection mappings and final text.

## Engine Composition

```text
Casting Module
  ↓
Calculation Module
(hexagrams / palace / Shi-Ying / Najia / relations / spirits / void)
  ↓
Traditional Analysis Module
(useful god / strength / generation-control / hidden-flying spirit / timing)
  ↓
Structured Output
```

The production implementation lives under `server/tools/liuyao/`, retains the public `calculateLiuyao` entry and keeps the existing `/api/v1/tools/liuyao/calculate` endpoint.

## Input Contract

Six three-coin tosses are ordered bottom-up. Full traditional analysis additionally requires explicit deterministic context:

```json
{
  "tosses": [[2,3,3],[3,2,2],[2,2,2],[3,3,2],[2,3,2],[3,2,3]],
  "analysisContext": {
    "topic": "career",
    "monthBranch": "wei",
    "dayStem": "wu",
    "dayBranch": "shen"
  }
}
```

`topic` comes from explicit user/runtime classification. Month branch and day pillar come from a deterministic calendar layer. The LLM never guesses them. Without this context, casting and structure still complete, while `analysis.status` becomes `context_required`.

## Evidence and Safety

Every traditional conclusion is accompanied by a rule identifier, conclusion and confidence. Timing is explicitly heuristic and never a promise. Health, legal and financial reflections remain subject to higher-level safety policy. Signed Reflection drafts store the analysis context and recalculate the Tool result during save to detect tampering.
